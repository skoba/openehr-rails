## R2 — #46(16 項)の 1・2: context の永続化 【例外報告。draft のまま止めている】

- Red を確認した spec(`spec/openehr_rails/rm/composition_committer_context_spec.rb`、8 例中 5 失敗):

- **計画と違った点(実測)**: 計画書 5 節は「`SELECT c/context/start_time/value` が値を返す」を見出しにしていた。
  context を持つ Composition では、openehr 2.4.3 の評価器が
  `unsupported path attribute "start_time" on a OpenEHR::RM::Composition::EventContext` を出す
  (`EventContext` は path attribute を宣言しておらず、`ALLOWED_TERMINAL_HOPS` は `magnitude`・`name`・`value` だけ)。
  master(変更前)でも、`Storable` で保存した Composition に対して同じエラーになる(実測。`composed_at` から context が入るため)。
  #46 の本文の「1 行返すが値は nil」は、context が nil のときの素通しだった
- この PR の副作用: canonical から context つきでコミットした Composition は、`c/context/...` の問い合わせが
  「nil の 1 行」から上のエラーに変わる。計画書に無い挙動の変更なので、**自己マージしていない**
- 上流(openehr-ruby)の `ec07936` も同じ(`path_evaluator.rb:23`、`rm/composition.rb:71` を読んだ。実行はしていない)。
  2.5.0 に入る #48(events/time)がこれを含むかは未確認
- anlage への影響: M2 の F の見出し「紹介日(context/start_time)で引ける」は、rails 0.9.0 だけでは満たせない
- `CanonicalSerializer` の往復に `context` を入れる件は入れていない。`Storable` 経由の Composition は
  canonical に `context` を持たないまま `context_start_time` 列が入るので、単純に出すと既存の往復の不変条件が崩れる(#46 に残す)

### 上流への問い(文面の案。投稿はこのセッションでは行わない)

> AQL: `c/context/start_time/value` raises `unsupported path attribute "start_time" on a
> OpenEHR::RM::Composition::EventContext` whenever the composition has a context (openehr 2.4.3;
> `path_evaluator.rb` `navigate_terminal`). `EventContext` is not PATHABLE and declares no path attributes,
> and `ALLOWED_TERMINAL_HOPS` has only `magnitude`, `name`, `value`. Reproduction: build a `Composition`
> with `context: EventContext.new(start_time:, setting:)`, run
> `SELECT c/context/start_time/value FROM EHR e CONTAINS COMPOSITION c`. Expected: the ISO 8601 value.
> Same for `c/context/setting/value` and `c/context/setting/defining_code/code_string`.
> Does 2.5.0 (#48 / #49) cover EVENT_CONTEXT, or is this a new issue for 2.5.x / 2.6.0?
