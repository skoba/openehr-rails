### #99 作成の側の重複【ゲート。実装には進まない】

計画書: `docs/design/99-ehr-subject-duplicate-plan.md`。

- 実測: `PUT /v1/ehr` で、同じ subject の EHR を 2 つ作れた(demo、2 回とも 201)。一意の制約は無い
- 仕様: ITS-REST の `POST /ehr` は、同じ subject id・namespace の組の EHR があれば 409("whenever EHR_STATUS is supplied")。**いまの実装は反している(bug)**。
  `PUT /ehr/{ehr_id}` の 409 は `ehr_id` の重複だけで、subject には触れない。RM の EHR IM は、1 人に複数の EHR があることを認めている(4.4.1、4.4.2)
- 決めてほしいこと:
  1. `PUT` も同じ subject の 2 つめを 409 にするか。推すのは「する」(入口によって結果を変えない。仕様に無い扱いとして書く)
  2. DB に一意の制約を足すか。推すのは「足さない」(migration を求めない。既存の重複で migration が止まる。同時の要求のすり抜けは変更履歴に書く)
  3. 作成の 409 の本文に、既にある `ehr_id` を入れるか。推すのは「入れる」(#95 の 409 とそろえる)
- semver: 既定の挙動が変わる(201 だった要求が 409 になる)ので minor とみる
