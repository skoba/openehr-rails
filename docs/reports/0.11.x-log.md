## R2 — #63 の計画(ゲート報告)【回答待ち。実装には進まない】

計画書: `docs/design/63-datetime-precision-plan.md`。要点:

- 前提がそろった。openehr-ruby#59 は openehr 2.6.0 で公開された(タグ `v2.6.0` が `83a1d18` を含む)
- 実測(master `a5e9a15`、openehr 2.6.1): 日付だけの値 `2026-03-01` が、グラフを通ると `2026-02-28T15:00:00Z` になる。
  精度が落ちるだけでなく、日付が変わる。オフセットも UTC に直される
- 上流の不具合を見つけた(実測): openehr 2.6.1 の `DvDateTime#magnitude` は、正のオフセットを逆向きに足す。
  `10:00+09:00` が `11:00Z` より後になる。いまはグラフが UTC に直してから AQL に渡しているので、表に出ていない
- 決めてほしいこと:
  1. 案 A(`text_value` に元の文字列を持つ。列を足さず、migration も要らない)か、案 B(列を足す)か。推すのは A
  2. AQL に元の文字列を渡すのは、上流の修正のあとにするか。推すのは「あと」:
     - canonical JSON だけ、先に元の値に戻す
     - そうしないと、正のオフセットを持つ値で、WHERE の結果が変わる
  3. 上流の Issue の文面の案(計画書 4 節)を、人間が openehr-ruby に投稿するか
