### #109(部分的な日時)

- PR [#117](https://github.com/skoba/openehr-rails/pull/117) → master `45912ab`
- `Rm::PartialTemporal`: 値を gem の ISO 8601 の読み取り(`ISO8601DateTime`、`ISO8601Date`)で読み、部分ごとに UTC の時点を組む

  - 読み取りの部分は、openehr 2.6.1・2.7.0・2.8.0・2.9.0 で同じ(実測)。gemspec の下限は変えていない
  - spec で、どの精度でも gem の magnitude と一致することを固定した
- DV_DATE の部分的な値(`2026`、`2026-11`)も落ちていた(`date` のカラムが nil にして、検証で落ちる)。同じ PR で直した。記録した文字は `text_value` に持つ
- gem が読めない文字(基本形式、`Time#to_s`)は、これまでどおり `Time.zone.parse`(regression pin)
- 既存の測った pin を 1 つ書き換えた: AQL の例 4。オフセットの無い文字は、手元の時刻帯(JST で `2026-01-31T15:00:00Z`)ではなく UTC で返る。CI(TZ=UTC)では、前もあとも同じ値
- Red: 29 例中 15 例が赤(`ArgumentError`、JST で読まれる、時が落ちる、DV_DATE の検証)

測った(実行時の経路、プロブレムリスト at0003 = `2026-11`、at0077 = `2026`、修正のあと):

### #110(Observation の日付と時刻)

- 直す前の測定(両方の経路)を Issue に書いた: https://github.com/skoba/openehr-rails/issues/110#issuecomment-7220355076
- PR [#118](https://github.com/skoba/openehr-rails/pull/118) → master `6467853`
- Observation の DV_DATE_TIME は、Condition の決まり(`date_time_string`)を通す。時までの値は日付までにする(FHIR の dateTime に、時だけの形は無い。公式の文書で確かめた)。
  Condition の時までの値も、記録のとおりに出していたので、合わせて直した
- DV_DATE は `valueDateTime`(R5 の Observation.value[x] に `date` は無い)。`TypeMap` を `dateTime` にした。生成するプロファイルと、POST の読み取りも変わる
- DV_TIME は `hh:mm:ss`。PR に書いた案:
  - 時刻帯があるときは、記録の時刻をそのまま出して、時刻帯を外す(FHIR の time は時刻帯を持てない。UTC に直すと、記録に無い時刻になる)
  - 時までの値は出さない(FHIR の time に、分の無い形は無い。分を作らない)
