## 3. openehr 2.5.0 の受け入れ

### 3.1 下限を上げるか

**案: 上げる(`'~> 2.5'`)。** 迂回(`populate_term_bindings!`)を消すと、2.5.0 より前の openehr では
`term_bindings` が nil に戻り、`code_bindings` が空になる。迂回の撤去と下限の引き上げは同じ PR にする。

- 下流: anlage は openehr を先に 2.5.0 へ上げる 2 段の計画なので、0.9.0 の下限と衝突しない

  2.5.0 でも no-op になる(推論: コードの形から)ので、0.9.0 は下限 `~> 2.3` のまま出せる

### 3.2 #31(term_bindings の迂回の撤去)

- 件数の差を固定している spec は**無い**(実測)。`parser_term_bindings_spec.rb` は `.first` と、

  fixture の埋め込みはアーキタイプごとに 1 回で、重複が起きない

### 3.4 openehr-ruby#36(STRICT 既定化)

番号の注意: このリポジトリの #36 は別件(診断確度の ConceptMap)。ここでいう #36 は openehr-ruby の Issue。

- 0.9.0 には入れない。`Opt::Parser#parse` は自前で Nokogiri を呼ぶ(1 節)ので、上流の既定を変えても
  このリポジトリの経路には届かない。届かせるには、rails 側で同じ ParseOptions を渡す変更と、
  STRICT で落ちる fixture の有無の確認が要る(未確認)
- Issue への記録は越境の書き込みになる。文面の案を下に置く(投稿するのは人間、または認可を受けたセッション。問い 6)

> openehr-rails overrides `OPTParser#parse` (`lib/openehr_rails/opt/parser.rb:14-39` at `c8a6841`) and calls
> `Nokogiri::XML::Document.parse(source)` itself, with no options. Changing the default ParseOptions in
> `OPTParser` therefore does not reach OPTs parsed through openehr-rails (uploads, the template registry,
> the FHIR profile repository). To make STRICT effective there, either expose the options as a constant or
> a hook the subclass can reuse, or move the "path or raw XML" handling upstream so the override can go.
> Not planned for openehr-rails 0.9.0.

  要素が 1 つでも concept だけには縮めない(テンプレートに要素を足したときに列名が変わらないようにする)。

  ルート名(「紹介先医療機関」など)と name 述語つきの path は、ルートごとの term が要る(openehr-ruby#58)。
  自前の XML 再解析で補うことはしない(依存の方針)。#58 が入った版のあとに別の Issue で足す
